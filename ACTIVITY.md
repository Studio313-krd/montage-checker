# Агрегация активности

Heartbeat остаётся неизменяемым исходным фактом, а таблицы `application_sessions`, `human_state_sessions`, `machine_state_sessions` и `render_sessions` содержат производные интервалы. Это позволяет повторно построить историю после доставки локальной очереди Agent и не хранить отдельную строку интервала на каждый 30-секундный срез.

## Границы интервалов

- Одинаковые process/path/title продолжают текущий application session.
- Смена процесса, пути или заголовка закрывает прежний application session временем нового heartbeat.
- Изменение `HumanState` или `MachineState` аналогично закрывает соответствующий независимый интервал.
- Отсутствие foreground process закрывает application session и не создаёт пустую запись.
- Неизвестное приложение получает `Neutral`; известное — classification из редактируемой таблицы `application_rules`.
- Открытый интервал имеет `ended_at_utc = NULL`. Частичные unique indexes гарантируют не более одного открытого интервала каждого типа на компьютер.
- Производственная session открывается при `MachineState=Render` или `MachineState=Proxy`, получает соответствующий `ProcessingType`, суммирует CPU для среднего, сохраняет максимум CPU, последний размер файла и максимальный confidence. Смена типа, программы или выходного файла разделяет сессии.

## Разрыв связи

Допустимый разрыв равен трём интервалам heartbeat, но не менее 90 секунд. При большем разрыве приложение, HumanState и MachineState закрываются через один ожидаемый heartbeat после последнего полученного события. До следующего события создаётся `HumanState=Offline`; application и machine time за этот промежуток не начисляются.

Фоновый worker раз в 30 секунд обрабатывает Agent, который перестал отвечать: закрывает его открытые application/machine sessions, закрывает текущее human-состояние и открывает Offline. При следующем heartbeat Agent снова становится Online, а затронутый фрагмент истории перестраивается по исходным событиям.

## Запоздавшие и параллельные события

Операции одного компьютера сериализуются PostgreSQL advisory lock внутри транзакции. Запоздавший heartbeat находит предшествующее событие и начало пересекающихся интервалов, удаляет только производный хвост от этой точки и строит его заново. Поэтому доставка SQLite outbox не создаёт пересечений и корректно вставляет пропущенную смену приложения.

Повтор UUID не запускает перестроение. Если такой UUID уже принадлежит другому устройству, Server возвращает `409 Conflict`.

## API чтения

`GET /api/employees/{employeeId}/activity/sessions` принимает:

- `fromUtc` и `toUtc` — необязательный UTC-диапазон, по умолчанию последние 24 часа, максимум 31 день;
- `computerId` — необязательный фильтр рабочего компьютера.

Ответ содержит четыре массива — `applications`, `humanStates`, `machineStates`, `renders` — и `durationSeconds`, обрезанную границами запроса и текущим временем. Массив `renders` исторически называется так, но различает `type=Render` и `type=Proxy`. Endpoint применяет ту же область видимости сотрудников, что и остальной API.

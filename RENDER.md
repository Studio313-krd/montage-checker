# Определение Render

RenderDetector работает в Windows Agent и подтверждает машинную работу только по совокупности сигналов. Сам факт запуска Premiere Pro, Media Encoder, After Effects, `aerender`, Resolve, `ffmpeg` или Blender даёт низкий confidence и не открывает Render session.

## Сигналы и confidence

Для каждого процесса из активного серверного правила Agent собирает CPU, working set, скорость process I/O read/write, число дочерних процессов и время запуска. Через отдельный необязательный provider добавляется максимум `utilization.gpu`/`utilization.encoder` из `nvidia-smi`. Если NVIDIA-инструмент недоступен, метрика остаётся `null`, а алгоритм продолжает работать.

Базовая оценка:

| Сигнал | Баллы |
| --- | ---: |
| Известный процесс | 20 |
| CPU выше порога правила | 30 |
| Process I/O write выше порога | 25 |
| GPU/encoder не ниже 20% | 10 |
| Создан или растёт выходной файл | 20 |
| Файл находится в контролируемой Render-папке | 10 |
| Известное видео-расширение | 5 |

Результат ограничивается диапазоном 0–100. Начальный порог правил равен 70: открытая программа получает только 20, а CPU + process I/O позволяют подтвердить Render без GPU. В heartbeat и `render_sessions` сохраняется confidence и русскоязычное объяснение сработавших сигналов.

## State machine

- сильный кандидат должен непрерывно существовать `confirmationSeconds` (по умолчанию 15 секунд);
- краткий провал сбрасывает окно подтверждения;
- активный Render продолжается, пока CPU, запись процесса или рост файла остаются выше порога;
- при ослаблении сигналов состояние удерживается `finishTimeoutSeconds` (по умолчанию 30 секунд), что защищает от коротких пауз кодека;
- исчезновение отслеживаемого процесса завершает Render немедленно.

Agent оценивает состояние каждые 5 секунд. При смене `MachineState` heartbeat ставится в очередь сразу, поэтому границы не ждут обычного 30-секундного интервала.

## Контролируемые папки

Для каждого компьютера задаются wildcard-путь, список расширений и простые шаблоны имён (`*_final.*`, `export_*.*`). Agent сравнивает metadata и размер максимум 500 последних файлов на папку; содержимое файлов не открывается и не передаётся. Первая проверка создаёт baseline, поэтому старые файлы не считаются только что созданными.

## Admin API

Endpoints требуют роль OWNER или ADMIN:

- `GET/POST /api/admin/render-rules`;
- `PUT /api/admin/render-rules/{ruleId}`;
- `GET/POST /api/admin/computers/{computerId}/render-folders`;
- `PUT/DELETE /api/admin/computers/{computerId}/render-folders/{folderId}`.

Agent получает активные правила и свои папки через `GET /api/agent/config`. Изменение конфигурации аудируется и не требует пересборки EXE. Экран управления этими настройками будет добавлен вместе с полным русскоязычным Web UI на соответствующем UI-этапе.

## Ограничения

Process I/O — счётчики всего процесса, поэтому необычная сторонняя запись может повысить confidence. Контролируемая папка и время подтверждения уменьшают этот риск. Файловый монитор использует polling, чтобы одинаково работать с локальными, сетевыми и wildcard-путями; это осознанно даёт задержку до одного цикла оценки.

# Ежедневный выбор монтажёра и общие ПК

## Зачем разделены компьютер и сотрудник

Одноразовый код Agent регистрирует физический компьютер и выдаёт ему device credential. Эта регистрация остаётся постоянной и не определяет, кто сегодня работает за ПК. Фактического сотрудника задаёт отдельная operator session, подтверждённая его PIN.

Такой контракт поддерживает оба сценария без искажения истории:

- один общий ПК в разные дни используют разные монтажёры;
- один монтажёр одновременно работает на двух или трёх ПК.

Каждый heartbeat и скриншот хранит фактический `employee_id`. Смена монтажёра закрывает интервалы предыдущего человека в момент переключения и открывает новые для выбранного. Уже записанная история не перепривязывается.

## Окно Agent

Agent `0.9.1` не собирает новые данные без действующей operator session. При первом запуске новой версии и далее каждый день после 06:00 по часовому поясу компании открывается полноэкранное окно поверх остальных окон. Крестика нет, `Alt+F4` блокируется.

Пользователь должен:

1. выбрать своё имя из списка активных сотрудников;
2. ввести личный PIN из четырёх цифр;
3. нажать **НАЧАТЬ СМЕНУ**.

Смена действует до следующего 06:00. Проверка срока выполняется не реже одного раза в 30 секунд. Если за компьютером не будет монтажёра, кнопка **Я НЕ МОНТАЖЕР** штатно завершает программу. Вернуть мониторинг после этого можно обычным двойным запуском EXE.

Передать ПК другому сотруднику в течение дня можно через tray: нажмите ЛКМ или ПКМ по значку MontageMonitor и выберите **Сменить монтажёра…**. Снова откроется обязательное полноэкранное окно без крестика и с заблокированным `Alt+F4`. Повторный enrollment token для этого не нужен.

## PIN в админке

При создании сотрудника Server генерирует случайный PIN от `0000` до `9999`, включая ведущие нули. Для существующих сотрудников PIN создаются автоматически при первом запуске обновлённого Server.

OWNER и ADMIN видят код в **Управление → Сотрудники → PIN монтажёра**. Кнопка **Новый PIN** сразу меняет код для последующих подтверждений. Уже начатая смена продолжает действовать до 06:00 или ручного переключения.

PIN намеренно короткий для ежедневного использования. Он не является самостоятельным ключом доступа: endpoint доступен только Agent с действительным device credential и ограничен десятью попытками в минуту по IP. В базе PIN хранится зашифрованным через ASP.NET Core Data Protection; ключи находятся в persistent volume `data_protection_keys`. Agent PIN не сохраняет.

## Обновление уже установленных Agent 0.8.0

Обновляйте в таком порядке:

1. Сделайте backup PostgreSQL и обновите Server/SPA в Portainer.
2. В веб-интерфейсе откройте **Управление → Сотрудники** и запишите PIN каждого монтажёра.
3. Убедитесь, что production работает. До замены EXE старые Agent `0.8.0` остаются совместимыми и продолжают прежний учёт.
4. На каждом рабочем ПК найдите папку текущего `MontageMonitor.Agent.exe`. Не удаляйте `%LocalAppData%\MontageMonitor`: там находятся device credential и offline-очередь.
5. Откройте tray MontageMonitor, выберите **Выход**, введите служебный пароль отключения `IDDQD` и дождитесь исчезновения значка.
6. Замените только `MontageMonitor.Agent.exe` новым файлом `0.9.1` в той же папке. Если путь изменился, один раз запустите новый EXE от обычного рабочего пользователя — Agent обновит свою задачу Task Scheduler.
7. Запустите новый EXE. Старый enrollment key вводить повторно не нужно: используется существующий защищённый `agent.json`.
8. Выберите человека, который сейчас работает на этом ПК, введите его PIN и нажмите **НАЧАТЬ СМЕНУ**.
9. Проверьте tray: строка **Монтажёр** должна показывать выбранное имя, статус через несколько секунд — **подключено**.

Если один сотрудник работает сразу на трёх ПК, на каждом из трёх выбирается одно и то же имя и вводится тот же PIN. Если ПК сегодня не используется монтажёром, нажмите **Я НЕ МОНТАЖЕР**.

## Excel при нескольких ПК

В `SUMMARY` человеческие состояния объединяются по сотруднику и времени с приоритетом `Active → Idle → Locked → Offline`. Поэтому три ПК, включённые один час, не создают три часа работы человека. Колонки **Использовано компьютеров** и **Параллельная работа** позволяют увидеть сам факт многокомпьютерной работы.

Render, Proxy и Background Processing являются машино-временем и суммируются по ПК. Это намеренно: три одновременных часовых рендера дают три машино-часа. В `TIMELINE`, `APPLICATIONS`, `RENDERS` и `IDLE` указан компьютер каждой записи.

Исторические данные, записанные Agent `0.8.0`, остаются привязаны к сотруднику, на которого когда-то был зарегистрирован ПК. Автоматически определить реального человека за прошлые дни невозможно; такие интервалы можно исправить только по известному расписанию «ПК + период + сотрудник». Новая схема делает корректными данные после установки `0.9.1`.

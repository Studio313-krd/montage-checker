# Ежедневный выбор монтажёра и общие ПК

Актуальная версия Agent — `0.10.3`. Она использует серверное время для событий и окончания смены, исправляет обработку отказов смены и добавляет диагностику связи; протокол входа остаётся совместимым с `0.10.1`. При обновлении `0.10.1`/`0.10.2` достаточно штатно завершить Agent через **Выход** с паролем `IDDQD`, заменить EXE в той же папке и запустить его. Если открыто обязательное окно выбора, завершите Agent кнопкой **Я НЕ МОНТАЖЕР**. Сохраните `%LocalAppData%\MontageMonitor` с настройками и очередью. Подробности: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Зачем разделены компьютер и сотрудник

При первом входе сотрудник выбирает своё имя и вводит пароль; Agent автоматически регистрирует физический компьютер и получает device credential. Идентификатор компьютера сохраняется при последующих входах и не определяет, кто сегодня работает за ПК. Фактического сотрудника задаёт отдельная operator session, подтверждённая его ID и паролем. Служебный логин остаётся в админке и API для обратной совместимости, но в desktop-программе не вводится.

Такой контракт поддерживает оба сценария без искажения истории:

- один общий ПК в разные дни используют разные монтажёры;
- один монтажёр одновременно работает на двух или трёх ПК.

Каждый heartbeat и скриншот хранит фактический `employee_id`. Смена монтажёра закрывает интервалы предыдущего человека в момент переключения и открывает новые для выбранного. Уже записанная история не перепривязывается.

## Окно Agent

Agent `0.10.1` не собирает новые данные без действующей operator session. При первом запуске новой версии и далее каждый день после 06:00 по часовому поясу компании открывается полноэкранное окно поверх остальных окон. Крестика нет, `Alt+F4` блокируется.

Пользователь должен:

1. выбрать своё имя в выпадающем списке;
2. ввести личный пароль из четырёх цифр;
3. нажать **ВОЙТИ И НАЧАТЬ СМЕНУ**.

Смена действует до следующего 06:00. Проверка срока выполняется не реже одного раза в 30 секунд. Если за компьютером не будет монтажёра, кнопка **Я НЕ МОНТАЖЕР** штатно завершает программу. Вернуть мониторинг после этого можно обычным двойным запуском EXE.

Передать ПК другому сотруднику в течение дня можно через tray: нажмите ЛКМ или ПКМ по значку MontageMonitor и выберите **Сменить монтажёра…**. Снова откроется обязательное полноэкранное окно без крестика и с заблокированным `Alt+F4`.

## Пароль Agent в админке

При создании сотрудника Server генерирует случайный пароль от `0000` до `9999`, включая ведущие нули. Для существующих сотрудников пароли создаются автоматически при первом запуске обновлённого Server.

OWNER и ADMIN видят пароль в **Управление → Сотрудники → Пароль Agent**. Кнопка **Создать новый пароль** сразу меняет его для последующих входов. Уже начатая смена продолжает действовать до 06:00 или ручного переключения.

Пароль намеренно короткий для ежедневного использования. Список для первоначального окна входа содержит только ID и отображаемые имена активных сотрудников и ограничен 60 запросами в минуту по IP; логины и пароли через него не выдаются. Первичное подключение ограничено пятью попытками в минуту по IP, а смена монтажёра с действительным device credential — десятью. Ответ одинаков для неизвестного сотрудника и неверного пароля. В базе пароль хранится зашифрованным через ASP.NET Core Data Protection; ключи находятся в persistent volume `data_protection_keys`. Agent пароль не сохраняет.

## Обновление уже установленных Agent 0.9.1/0.10.0

Обновляйте в таком порядке:

1. Сделайте backup PostgreSQL и обновите Server/SPA в Portainer.
2. В веб-интерфейсе откройте **Управление → Сотрудники** и запишите имя и пароль каждого монтажёра.
3. Убедитесь, что production работает. До замены EXE старые Agent `0.9.1` и `0.10.0` продолжают передавать heartbeat и скриншоты по действующему device credential.
4. На каждом рабочем ПК найдите папку текущего `MontageMonitor.Agent.exe`. Не удаляйте `%LocalAppData%\MontageMonitor`: там находятся device credential и offline-очередь.
5. Откройте tray MontageMonitor, выберите **Выход**, введите служебный пароль отключения `IDDQD` и дождитесь исчезновения значка.
6. Замените только `MontageMonitor.Agent.exe` новым файлом `0.10.1` в той же папке. Если путь изменился, один раз запустите новый EXE от обычного рабочего пользователя — Agent обновит свою задачу Task Scheduler.
7. Запустите новый EXE. Не удаляйте `agent.json`: Agent сохранит device credential, забудет старый адрес сервера и один раз принудительно откроет новое окно входа.
8. Выберите имя человека, который сейчас работает на этом ПК, введите его пароль и нажмите **ВОЙТИ И НАЧАТЬ СМЕНУ**.
9. Проверьте tray: строка **Монтажёр** должна показывать выбранное имя, статус через несколько секунд — **подключено**.

Если один сотрудник работает сразу на трёх ПК, на каждом из трёх выбирается его имя и вводится пароль. Если ПК сегодня не используется монтажёром, нажмите **Я НЕ МОНТАЖЕР**.

## Excel при нескольких ПК

В `SUMMARY` человеческие состояния объединяются по сотруднику и времени с приоритетом `Active → Idle → Locked → Offline`. Поэтому три ПК, включённые один час, не создают три часа работы человека. Колонки **Использовано компьютеров** и **Параллельная работа** позволяют увидеть сам факт многокомпьютерной работы.

Render, Proxy и Background Processing являются машино-временем и суммируются по ПК. Это намеренно: три одновременных часовых рендера дают три машино-часа. В `TIMELINE`, `APPLICATIONS`, `RENDERS` и `IDLE` указан компьютер каждой записи.

Исторические данные, записанные Agent `0.8.0`, остаются привязаны к сотруднику, на которого когда-то был зарегистрирован ПК. Автоматически определить реального человека за прошлые дни невозможно; такие интервалы можно исправить только по известному расписанию «ПК + период + сотрудник». Новая схема делает корректными данные после установки Agent с ежедневным входом; версия `0.10.1` показывает актуальный список имён и отправляет выбранный ID с паролем.

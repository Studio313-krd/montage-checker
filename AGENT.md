# Windows Agent

`MontageMonitor.Agent` — обычное видимое WinForms-приложение для Windows 10/11. Пользователь работает только с `MontageMonitor.Agent.exe`: консольное окно, CMD/PowerShell и отдельно установленный .NET Runtime не нужны.

## Подготовка файла

Разработчик или администратор выпускает self-contained single-file сборку:

```powershell
dotnet publish src/MontageMonitor.Agent -p:PublishProfile=Windows-x64 -o artifacts/agent/win-x64
```

Пользователю передаётся единственный файл `artifacts/agent/win-x64/MontageMonitor.Agent.exe`.

## Первое подключение

1. OWNER или ADMIN создаёт сотрудника. Система сразу выдаёт ему случайный пароль из четырёх цифр.
2. Монтажёр запускает EXE двойным щелчком.
3. В русском окне выбирает своё отображаемое имя из списка сотрудников и вводит четырёхзначный пароль.
4. Agent автоматически подключается только к `https://montage.checker.studio313.ru/`, регистрирует физический компьютер и начинает смену.
5. Выбранный сотрудник и статус доступны через значок MontageMonitor в системном tray.

Поля адреса сервера и одноразового кода в Agent отсутствуют. Пароль не сохраняется: после успешного входа Agent хранит только device credential, защищённый Windows DPAPI.

## Ежедневный выбор монтажёра

Начиная с Agent `0.9.0`, устройство и работающий за ним человек учитываются раздельно. Один и тот же зарегистрированный компьютер можно использовать разным сотрудникам, а один сотрудник может одновременно работать на нескольких компьютерах.

Смена выбора действует до следующего 06:00 по часовому поясу компании. После истечения смены Agent прекращает сбор новых данных и не позволяет закрыть полноэкранное окно через крестик или `Alt+F4`, пока пользователь не выполнит одно из действий:

- выберет своё имя и введёт четырёхзначный пароль, затем нажмёт **ВОЙТИ И НАЧАТЬ СМЕНУ**;
- нажмёт большую кнопку **Я НЕ МОНТАЖЕР**, которая штатно завершает Agent.

Выбранного сотрудника можно сменить раньше через пункт tray **Сменить монтажёра…**. Пароль хранится на Server в обратимо зашифрованном виде и никогда не сохраняется в `agent.json` или SQLite-очереди. OWNER и ADMIN видят его в разделе **Управление → Сотрудники** и могут создать новый. Подробности и обновление уже установленных EXE: [OPERATOR_SELECTION.md](OPERATOR_SELECTION.md).

## Что отправляет heartbeat

По умолчанию раз в 30 секунд Agent отправляет:

- версию Agent, имя компьютера и пользователя Windows;
- UTC-время события;
- `HumanState` на основе времени последнего ввода и блокировки сеанса;
- foreground process, путь EXE и заголовок активного окна;
- загрузку CPU и оперативной памяти;
- независимый `MachineState`, включая подтверждённый Render;
- при Render — процесс, время его запуска, CPU, working set, скорость чтения/записи process I/O, число дочерних процессов, необязательную загрузку GPU, растущий выходной файл, confidence и русскоязычную причину.
- при Proxy — encoder, process CPU/I/O, растущий видеофайл в Proxy-папке, совпадение filename rule, confidence и русскоязычную причину.

Интервал heartbeat и порог idle Agent получает из server configuration. UUID события генерируется на клиенте, а Server принимает повтор идемпотентно и агрегирует последовательные одинаковые состояния в интервалы продолжительности.

RenderDetector проверяет только процессы из серверных правил и не считает сам факт открытого Premiere/Resolve признаком работы. Метрики Windows изолированы за интерфейсами, а state machine покрыта unit-тестами на искусственных срезах. GPU читается через `nvidia-smi`, если он доступен; отсутствие NVIDIA/GPU не мешает подтверждению по CPU и записи. Папки Render опрашиваются по wildcard-пути и шаблонам имён без чтения содержимого файлов.

ProxyDetector работает отдельно и требует известный encoder вместе с ростом видеофайла в настроенной Proxy-папке. Имя наподобие `*_Proxy.mov` повышает confidence, но не является самостоятельным доказательством. Если ошибочно пересекающиеся настройки одновременно классифицируют один растущий файл как Render и Proxy, Render-папка имеет приоритет.

## Работа без сети и секреты

Каждый heartbeat сначала записывается в `%LocalAppData%\MontageMonitor\queue.db`. После восстановления связи очередь отправляется от старых событий к новым; неудачные попытки используют увеличивающуюся задержку до пяти минут.

Скриншоты имеют отдельную таблицу в той же SQLite-базе и отдельные локальные JPEG-файлы. Сначала изображение атомарно попадает в локальную очередь, затем загружается отдельным multipart-запросом. Успешно принятый или окончательно отклонённый файл удаляется; временная ошибка сети оставляет его для повторной отправки с задержкой до пяти минут.

Захват выполняется только в интерактивной незаблокированной сессии и только когда он включён для сотрудника. Agent получает с Server интервал 1–60 минут, режим основного/всех мониторов, максимальную ширину, JPEG quality 55–65 и privacy-список процессов. Если foreground process входит в этот список, изображение не создаётся, а через надёжную heartbeat-очередь отправляется только событие `SCREENSHOT_SKIPPED_PRIVACY`. Содержимое окон, клавиатурный ввод и файлы приложений Agent не читает.

Настройки находятся в `%LocalAppData%\MontageMonitor\agent.json`. Device credential защищён Windows DPAPI в контексте текущего пользователя, а на Server хранится только его SHA-256 hash. SQLite-очередь не содержит credential.

## Автозапуск и восстановление

После первого успешного входа Agent сам создаёт задачу `MontageMonitor Agent` в Windows Task Scheduler для текущего пользователя:

- запуск при входе пользователя в Windows;
- только в интерактивной сессии, чтобы Agent видел foreground window и находился в tray;
- запуск того же EXE, из которого выполнена регистрация;
- повторный запуск через одну минуту после аварийного завершения;
- защита от второго экземпляра через mutex пользователя Windows.

Если Agent завершился из-за необработанной ошибки, он возвращает ненулевой exit code, и Task Scheduler запускает его снова. Штатное отключение через меню tray или кнопку **Я НЕ МОНТАЖЕР** возвращает нулевой exit code и не перезапускается.

## Штатное отключение

Откройте меню значка MontageMonitor в tray, выберите **Выход** и введите пароль `IDDQD`. Пароль сравнивается локально по hash и не передаётся на Server. Без правильного пароля штатно отключить приложение через его интерфейс нельзя.

Пункт **Войти заново…** открывает окно выбора сотрудника и пароля и после успешного входа заменяет старый device credential. Для обычной передачи общего ПК другому монтажёру используйте **Сменить монтажёра…**: это сохраняет идентификатор компьютера и уже записанную историю.
